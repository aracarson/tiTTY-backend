API source IP globe visualization

Goal
- Extend the existing SQLite API usage report so source IP activity can be geolocated and displayed on an interactive globe/map.
- Preserve the current source/endpoint metrics while keeping the visualization useful for traffic patterns, abuse review, and operational monitoring.

Next steps
- [ ] Decide the privacy and retention policy before enabling geolocation: document who can access exact IPs, how long raw IPs are retained, and whether reports should use truncated/anonymized IPs.
- [ ] Confirm proxy trust boundaries: only accept `X-Forwarded-For`/`X-Real-IP` from the local Caddy ingress, and keep port 8080 closed to the public internet.
- [ ] Choose a GeoIP provider and database format. Prefer a local MaxMind GeoLite2/GeoIP2 database or another licensed offline database so request handling does not call an external geolocation service.
- [ ] Add a scheduled GeoIP database update with checksum/signature verification, rollback to the last known-good database, and a clear record of database version and license/attribution.
- [ ] Add a geolocation enrichment job that reads `source-summary.csv` or SQLite aggregates and writes derived fields such as country, region, city, latitude, longitude, timezone, ASN, and organization. Keep geolocation out of the request path.
- [ ] Define handling for private, reserved, invalid, `unknown`, IPv4, and IPv6 addresses. Do not attempt to geolocate private/reserved addresses, and label approximate results as approximate.
- [ ] Add a derived SQLite table or report artifact keyed by IP plus GeoIP database version, with an expiry/version strategy so locations can be refreshed without rewriting request metrics.
- [ ] Export a map-friendly dataset such as `source-geolocation.json` containing aggregated points only: latitude, longitude, request count, endpoint count, status classes, first/last seen, and a coarse location label.
- [ ] Avoid exposing exact IP addresses in the public dashboard or S3 report URL. Keep an operator-only detailed report separate from a redacted visualization dataset.
- [ ] Add an interactive globe/map view to the generated dashboard. Use a maintained browser mapping library or globe library, load a country/coastline asset, and render aggregated points or heatmap cells sized by request volume.
- [ ] Add filters for time window, endpoint, status class, country/region, request volume, and suspicious traffic. Show a table beside the map so the visualization remains usable without WebGL.
- [ ] Add a drill-down from a map point to source/endpoint metrics without revealing more IP detail than the access policy permits.
- [ ] Make the map dataset bounded: cap point count, aggregate nearby points, and paginate or limit long time windows so one report cannot exhaust browser memory.
- [ ] Add tests for GeoIP enrichment, cache invalidation, unknown/private addresses, IPv4-mapped IPv6, malformed input, aggregation, and redaction.
- [ ] Add an end-to-end verification step: generate a report, confirm the map JSON is present, open the dashboard locally, and verify ordinary traffic and malicious probes still produce the expected WAF/API metrics.

Suggested report artifacts
- `source-geolocation.json`: redacted aggregated points for the map.
- `source-geolocation.csv`: operator export with the selected derived fields.
- `geoip-database.json`: provider, database version, release date, checksum, and attribution.
- `index.html`: existing API dashboard extended with the globe/map and filters.

Acceptance criteria
- [ ] A scheduled report can generate the map dataset from existing API aggregates without making live third-party requests per API call.
- [ ] The globe displays traffic by approximate location and supports the selected time and endpoint filters.
- [ ] Unknown/private/reserved sources do not create misleading map points.
- [ ] Reports do not leak exact IP addresses to viewers who only need the visualization.
- [ ] GeoIP failures do not prevent API service, metrics collection, backups, or normal dashboard generation.
- [ ] The implementation documents provider licensing, accuracy limitations, retention, and the operational update/rollback procedure.
